# Changelog

All notable changes to Playlisterr are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/), and versions aim to follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

First public release in preparation. Everything below is the initial feature
set.

### Added
- Per-user Plex recommendation rows generated by a local or hosted LLM from
  titles you already own, one row per library ("Generated Movies", …).
- Delivery as per-account playlists (private to each viewer, owner included) or
  server-wide collections (real "Recommended" library rows).
- Per-library taste analysis, so a shared account's kids-films row follows the
  kids' viewing rather than the account owner's.
- Web UI with a two-click setup wizard (Sign in with Plex, auto-detect the LLM
  endpoint), settings, per-user enable/disable, run history, logs and a
  scheduler.
- Generate / Publish-these-picks / Generate-&-publish, so an approved set can
  be published unchanged.
- Fixture record/replay for developing with no Plex server, plus a shipped
  fictional sample set so `run --offline` works on a fresh clone with no setup.
- Webhook run notifications (ntfy, Gotify, Discord, Slack, or generic JSON) on
  completion and on failure.
- Per-title veto: a "never recommend" button on every pick and an editable
  exclude list.
- Health panel: probes whether Plex and the model are actually reachable, not
  just configured, surfaced as a header pill and a Home banner.
- Config backup (settings + state as a zip), log download, and log rotation.
- Standard-library-only Python core; no build step for the UI.

### Security
- Sensitive endpoints require the API key regardless of the auth setting, and
  never pair a caller-supplied URL with a stored secret, closing CSRF/SSRF
  token-exfiltration paths.
- Recorded fixtures redact tokens and emails from response bodies at write
  time.
